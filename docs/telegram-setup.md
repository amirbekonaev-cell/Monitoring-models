# Настройка Telegram-бота для уведомлений

Бот уже создан через @BotFather, токен у вас на руках. Дальше — разовая ручная настройка группы.

## 1. Создать группу

1. В Telegram: **Новая группа** → добавьте хотя бы одного участника (можно только себя, потом
   удалите) → задайте название, например «QazCloud — упоминания».
2. Группа создана.

## 2. Добавить бота в группу

1. Откройте группу → **Участники** → **Добавить участника**.
2. Введите `@username` вашего бота (тот, что вы задавали в @BotFather при создании).
3. Добавьте его.

## 3. Сделать бота администратором

Это нужно для надёжной доставки сообщений (и чтобы бот видел свои же апдейты в группе):

1. **Участники** → выберите бота → **Назначить администратором**.
2. Права можно оставить минимальные — важно только, что он не выступает как «ограниченный
   участник».

## 4. Прописать токен бота в `.env`

В корне проекта, в файле `.env` (не в `.env.example`, не в код):

```
TELEGRAM_BOT_TOKEN=<токен от @BotFather>
```

Никогда не присылайте токен в чат/коммит/лог. Если токен когда-либо оказался виден в переписке
или публичном месте — считайте его скомпрометированным и замените через `/revoke` у @BotFather.

## 5. Получить chat_id группы

1. Отправьте в группу любое сообщение (например «привет»), чтобы Telegram сохранил
   событие для бота — API отдаёт только последние ~24 часа через `getUpdates`.
2. Запустите скрипт:

   ```sh
   cd backend
   npm install   # если ещё не делали
   npm run get-chat-id
   ```

3. Скрипт выведет что-то вида:

   ```
   Найденные группы:
     chat_id=-1001234567890  title="QazCloud — упоминания"  type=supergroup
   ```

4. Скопируйте `chat_id` (со знаком «минус» — это нормально для групп) в `.env`:

   ```
   TELEGRAM_CHAT_ID=-1001234567890
   ```

5. Если группа не нашлась — проверьте: бот добавлен и назначен админом, в группе после этого
   было отправлено новое сообщение, прошло не больше суток. Отправьте сообщение ещё раз и
   запустите скрипт заново.

## 6. Перезапустить стенд

```sh
docker compose up --build
```

С этого момента новые упоминания, найденные при обычном мониторинге (не при первом
историческом сборе по источнику), будут приходить в группу в течение нескольких минут после
появления в базе.

## Если что-то не так

- **Бота убрали из админов / удалили группу** — отправка упадёт с понятной ошибкой в логах
  backend (`docker compose logs -f backend`, ищите `Failed to send Telegram notification`), сам
  сборщик данных при этом продолжает работать как ни в чём не бывало — рассылка идёт по
  отдельной очереди специально для этой изоляции.
- **Отправка повторяется несколько раз с задержкой** — это штатный ретрай BullMQ при временной
  ошибке (например, сеть недоступна); если она не исчезает — проверьте `TELEGRAM_CHAT_ID` и
  права бота в группе.
